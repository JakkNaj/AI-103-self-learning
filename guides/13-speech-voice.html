One-shot recognition handles a short utterance; continuous recognition listens until stopped. Offline batch is not the right mechanism for low-latency interim captions. A model accepting audio may support reasoning about tone beyond a plain transcript, but verify its capabilities. Speech-to-text overview

Standard voice-agent pipeline

Capture audio → speech-to-text → agent/model reasoning and tool operations → text-to-speech → play audio. Translation can follow recognition and precede target-language synthesis. Audio and transcript can contain PII; apply the same privacy controls as typed messages.

Voice Live integrates a real-time voice interaction pipeline with supported models/agents. It uses WebSocket events in the documented backend integration. Configure the session/audio formats and handle streamed input/output, turn detection and interruption. Barge-in: when the user speaks during playback, stop/cancel the appropriate current output and continue handling the new turn. It is not ordinary offline file transcription. Voice Live

Batch transcription: complete sequence

Prepare supported audio in accessible storage → submit job with source URLs, locale and optional supported settings/model → poll status → retrieve result files → read transcript/timestamps/diarization → handle failures and retention.

Diarization attributes speaker segments; it is not automatically a verified real-world speaker identity. For custom batch recognition, the request references a model URI; it need not point to a hosted custom endpoint. Local filesystem paths are not remotely downloadable Blob URLs. Batch requests

Adaptation versus pronunciation

  • A few uncommon names → try a phrase list for recognition bias.
  • Broader persistent domain STT errors → evaluate Custom Speech against held-out audio/reference transcripts.
  • Synthesized pronunciation/pauses → SSML, not a recognition model.
  • Learner fluency/accuracy → pronunciation assessment, not TTS.

SSML can specify voice, phonemes/pronunciation, breaks and supported prosody. It does not configure Search or grant permissions. Pronunciation output includes task-specific scores; supported metrics/granularity depend on locale/configuration. SSML, pronunciation assessment

Custom Speech expiration: two different outcomes

Route using expired modelDocumented behaviorFix
Custom endpointFalls back to newest base model for the locale; domain accuracy can declineUpdate the endpoint to a valid custom model
Batch request explicitly referencing the modelFails with a 4xx errorUse a valid model URI, or omit model to use latest base model

Do not assume both routes fail identically or both fall back. Retrain/update periodically and monitor expiration and quality. Custom Speech lifecycle

Translation, identifiers and authentication traps

SpeechTranslationConfig separates source recognition locale from target translation languages. For multiple translated texts that must all be spoken, synthesize each with a suitable target voice unless the chosen API explicitly supports the desired direct output.

Speech REST content type must match the actual audio encoding/rate. A resource key and endpoint from different resource/region contexts can produce 401; fix that before changing the text prompt. A Custom Speech project ID, Foundry project ID, model URI and endpoint URL identify different artifacts — fill the property actually requested.

Study by decision

  • Real-time vs fast vs batch transcription — 9 questions. Real-time streams live audio; fast transcription processes supported recordings quickly; batch handles asynchronous stored-audio workloads. Match scale and latency requirements.
  • Speech SDK events, results & REST — 9 questions. Use recognizing for interim text and recognized for final text. Interpret NoMatch separately from cancellation; match audio format/locale/key/region in REST.
  • TTS, voices & SSML — 11 questions. Text to speech synthesizes audio. SSML controls supported pauses, pronunciation, prosody and voice settings.
  • Phrase lists vs Custom Speech — 6 questions. Try a phrase list for a small vocabulary; evaluate Custom Speech on representative reference transcriptions for persistent domain/noise errors.
  • Expired custom models & batch fallback — 5 questions. Preserve the distinction: documented custom endpoint behavior can fall back to a base model; batch requests naming an expired model can fail. Remove the expired model reference for documented base-model batch behavior.
  • Live speech translation & target synthesis — 11 questions. Configure recognition source and target languages; stream translation where needed. Synthesize translated text separately for multiple spoken outputs when appropriate.
  • Voice Live transport, interruption & agents — 11 questions. Use the supported real-time event/transport design. Handle interruption by stopping stale audio; distinguish agent-backed and directly instructed sessions.
  • Custom Voice, avatars & pronunciation scores — 11 questions. Custom Voice needs its documented approval/consent process; avatars synthesize speaking visuals; pronunciation assessment scores supported speech dimensions.
  • Audio reasoning, diarization & Speech MCP — 6 questions. Choose models/output preserving necessary audio cues and speaker/time information. Validate audio references and MCP tool results against the actual execution.
