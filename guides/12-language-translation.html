Prebuilt tool versus generative prompt

Choose a specialized operation when it directly meets a standard task and you want repeatable typed outputs without maintaining a generative prompt. Use domain instructions/examples/schema when the task requires custom categories, compliance-aware summaries or combined extraction/reasoning.

For domain output: define exact fields/allowed values → ground in the supplied text → represent missing facts explicitly → validate schema and facts → evaluate on representative cases. Do not turn “not mentioned” into “confirmed absent.” A fluent summary that omits an obligation can fail the task.

PII SDK workflow

  1. Supply supported text/documents with suitable language settings.
  2. Call the PII operation, such as recognize_pii_entities.
  3. Inspect each result; a batch can contain individual errors.
  4. Use successful result redacted_text where the downstream need is obscured text.
  5. Retain only necessary detection metadata and protect it.

entities describes detections/offsets; redacted_text is the transformed output. Detection does not automatically sanitize a logger that still writes the original string. Run redaction before broad diagnostic storage. PII redaction

Mixed-language limitation: the extra steps

Translator documents incorrect/incomplete translation for sentences containing mixed languages. A mitigation pipeline is:

  1. Split into language-homogeneous segments.
  2. Determine/specify each segment's intended source language.
  3. Translate each segment to the target language.
  4. Reconstruct the original ordering.
  5. Review meaning and terminology where required.

Increasing temperature or changing Speech voices does not fix a mixed-language Text API input. Auto-detection alone is not a guarantee that one mixed sentence is handled correctly. Known Translator issues

Language MCP integration

Discover available tool schemas → register/configure the integration → model requests the operation → configured client/service executes it → return the actual result → summarize. MCP exposes capabilities; it does not turn every operation into a new reasoning model or remove validation/permissions.

Study by decision

  • Language detection, NER & key phrases — 14 questions. Match the operation to the requested output; use entity spans for NER and appropriate topic/key-phrase analysis for themes.
  • Sentiment vs opinion mining — 8 questions. Sentiment classifies message tone; opinion mining associates sentiment with specific targets/aspects.
  • PII detection & redacted_text — 6 questions. Use PII detection results and service-produced redacted text where appropriate; validate coverage for the privacy requirement.
  • Domain extraction & unknown facts — 9 questions. Specify domain terminology/schema, validate values against evidence, and represent missing/unknown information explicitly.
  • Text translation, documents & transliteration — 13 questions. Use Translator for supported text languages, Document Translation for stored documents/structure, and transliteration for script conversion without changing language.
  • Mixed-language segmentation & Translator REST — 6 questions. Split into language-homogeneous segments, translate each with the intended source language, then recombine in order. Check REST language parameters and regional headers.
