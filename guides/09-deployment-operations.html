Deployment choice has two axes

Capacity/billing: Standard pay-per-token; Provisioned reserves PTU capacity; Batch processes offline requests asynchronously.

Processing scope: Global; a Microsoft-defined Data Zone; or the geography-based/region-specific option documented for the model. Combine the two constraints rather than selecting on one word.

Version correction: current documentation describes Standard processing within an Azure geography. Do not equate a deployment's location with a universal single-datacenter/single-region processing guarantee. If the question explicitly requires one region, verify that precise contract. Data Zone is broader than a single region; Global does not guarantee an EU boundary. Deployment types

Managed compute hosting of supported open models is a different deployment mechanism; it is not another spelling of Standard pay-per-token. Model support, context limits, modalities and lifecycle vary. Check the selected model/API rather than transfer parameters from another model.

Resource, project, model and agent are different artifacts

  • Foundry resource: Azure management/billing boundary.
  • Project: organizes agents, connections, development and evaluation.
  • Model deployment: concrete configured endpoint/deployment name.
  • Agent definition/version: instructions, selected model and tools.
  • Published agent endpoint/application: deployment lifecycle for invocation/distribution.

Where the API expects an Azure deployment name, supply that name, even if it differs from the underlying model family. For project administration use the project client/endpoint; for inference use the compatible client and documented endpoint. Publishing an agent version is a separate step from creating it.

Quota and throttling

For applicable Standard quotas, the pool is scoped by subscription, region, model and deployment type. Assigning TPM to deployments consumes that pool.

Example: quota 240k TPM; existing allocation 160k; request 100k → total 260k exceeds the pool. Free/reallocate quota or obtain an increase. Dynamic quota is opportunistic extra throughput, not a guaranteed extra allocation or free capacity.

On 429: respect server retry guidance → bounded exponential backoff/jitter → cap concurrency/shape traffic → investigate TPM/RPM and capacity. Short bursts can throttle even when average RPM looks low. More retries do not fix sustained overload; retries of state-changing tools also need idempotency. Quota management

Private connectivity needs all pieces

Private endpoint + reachable network route + correct private DNS + target permissions. A private endpoint with the hostname still resolving publicly does not satisfy the intended path. A CI runner outside the permitted network can fail even when a developer inside it succeeds.

Inspect each service dependency: Foundry, Search, Storage, model/embedding endpoints and external tools. An inbound private endpoint does not automatically isolate every outbound agent request. Disabling public access before providing a working private path breaks connectivity. Foundry private connectivity, agent networking

CI/CD and cost questions

Version prompts, model/version choices, tool schemas, retrieval settings and deployment definitions. Run representative quality/safety evaluations → gate release → stage rollout → monitor → keep rollback available. Preview status and retirement dates are lifecycle constraints; verify them before promising production behavior.

If traffic is unchanged but cost rises, inspect input tokens, output tokens, model routing and number of model/tool calls. Huge context → retrieve fewer useful passages. Simple tasks on an expensive model → evaluate smaller-model routing with fallback. Loops → enforce stop limits. Do not remove required evidence merely to reduce tokens.

Study by decision

  • Standard vs Provisioned vs Batch — 14 scored questions. Standard fits pay-per-use interactive workloads; Provisioned reserves capacity for justified sustained throughput; Batch fits eligible asynchronous backlogs.
  • Regional vs Data Zone vs Global — 6 scored questions. Choose the documented processing scope supported by the specific model/SKU. Data Zone is a zone, not one region.
  • TPM allocation, 429 & retries — 14 scored questions. Distinguish deployment quota allocation from runtime limits; inspect TPM/RPM and burst behavior. Use bounded backoff respecting Retry-After; change capacity when justified.
  • Private endpoints, routing & DNS — 14 scored questions. Validate private endpoints, reachable routes and private DNS for each required service and build/runtime caller.
  • Preview, retirement & migration — 2 scored questions. Check lifecycle metadata and support commitments; validate replacements before retirement and production adoption.
  • Versioned release & CI/CD — 10 scored questions. Version prompts, schemas, tools, retrieval settings and model configuration; evaluate before promotion and retain rollback plus monitoring.
  • Foundry resource boundary & CLI — 7 scored questions. Choose the documented Foundry resource kind and configuration for the projects/models/agents/tools boundary.
  • Reduce context & capacity cost — 2 scored questions. Retrieve targeted context, bound output and unnecessary tool rounds, and size capacity from measured demand and quality targets.
