Visual question answering: evidence flow

  1. Select a deployment supporting image input.
  2. Supply the question and actual image in the request's supported representation.
  3. Identify images clearly if there are several.
  4. Choose supported detail settings appropriate to the task.
  5. Require answers grounded in what is visible, with an uncertainty path.
  6. Validate consequential interpretations; request better evidence if needed.

Responses input clues: content items can include input_text and input_image; Chat Completions uses its own content types/envelope. A data URL includes encoded image data; a model-inaccessible local path supplies no pixels to a remote API.

If the connector is outside the frame or a label is illegible, say the evidence is missing. A generated view or a similar product picture cannot establish the real object's condition. Vision inputs

Captions and accessibility

Short caption/alt text: relevant visible content and purpose, concise enough for the context. Extended description: axes/trends/relationships or detail that a complex chart/scene needs. Describe the relevant image, avoid invented identities/conditions and represent uncertainty.

“More detailed” does not mean speculate. “One sentence” is an output requirement; increasing image detail is an input-processing choice. They solve different problems.

Image generation and decoding

Prompt + supported reference/control settings → generate → inspect safety/task compliance → decode/store output in its returned format. Verify supported size, quality and editing parameters for the selected model/API.

For an inline image response, b64_json contains base64-encoded bytes. Decode, then write binary data:

import base64
from pathlib import Path

image_bytes = base64.b64decode(result.data[0].b64_json)
Path("output.png").write_bytes(image_bytes)

Writing the encoded string directly does not create the image. Do not treat it as a download URL. A transparent background needs a supported transparency setting and an alpha-capable format such as PNG; JPEG cannot preserve an alpha channel. Azure image generation/editing

Localized edit: all the required inputs

  1. Supply the source image containing the subject to preserve.
  2. Supply a supported mask aligned with the source dimensions.
  3. Mark the intended editable area using that API's mask semantics.
  4. Describe the change and what must remain consistent.
  5. Select fidelity/output settings supported by the model.
  6. Inspect the result for unintended changes before accepting it.

For documented GPT-image PNG masks, transparent mask areas indicate editable regions. A mask guides the edit; do not assume every generated pixel outside it is guaranteed identical. If exact pixel preservation is mandatory, verify/composite the unchanged region as part of the product workflow.

Example: approved bicycle, new background → reference/source + background mask + preservation instruction + compatible fidelity. Text-only regeneration cannot offer the same source constraint. High fidelity strengthens adherence; it does not make a missing source/mask unnecessary. Mask and fidelity behavior

Video generation versus video analysis

Generation: submit supported prompt/reference → receive job ID → poll → if successful, retrieve generated media → inspect → store/publish under policy. A failed job is not downloadable success. A supported remix/edit operation identifies the existing generated clip and requested modification; support varies by model/API.

Analysis: process existing segments/frames and audio → preserve timestamps/transcript/visual context → extract fields/descriptions → answer with references to the relevant time interval. Merging distant events without time context can invent a false sequence. Content Understanding video

Safety and version traps

Combine visual moderation, indirect-attack handling for embedded text, grounded answers and specific visual-policy checks. A watermark does not replace these controls.

Older image questions may describe DALL-E output URLs or parameters. Current Azure GPT-image questions in our bank use base64 output/editing controls. Learn the response shape shown; do not assume all image models return the same fields.

Study by decision

  • Visual Q&A & multimodal message inputs — 17 questions. Supply the actual image plus a clear text task, label multiple images, and limit conclusions to observable evidence.
  • Alt text, captions & extended descriptions — 14 questions. Describe observable purpose/content concisely for alt text; add longer descriptions when complex structure/trends require them.
  • Image generation, transparency & base64 — 18 questions. Use the supported Images API/model configuration. Decode inline base64 to bytes; choose transparency-compatible formats/settings.
  • Reference images, masks & bounded edits — 20 questions. Supply the source image and compatible aligned mask for bounded edits, using the selected model/API semantics and fidelity controls.
  • Video generation, remix & job states — 11 questions. Submit supported text/reference inputs, track the job to a terminal state, and download only successful output. Use the documented base-media ID for remix.
  • Video understanding & time-aligned evidence — 9 questions. Use a supported video analysis capability and preserve intervals, transcript, visual evidence and metadata for the question.
