Prompt engineering: steps and controls

  1. Specify task, audience and boundaries.
  2. Add relevant context, clearly separated from instructions.
  3. Define the output contract: headings, schema, citations, unknown values.
  4. Provide representative examples where useful.
  5. Choose supported generation controls.
  6. Evaluate on held-out cases; version the resulting prompt and configuration.

temperature affects sampling randomness where the model supports it; lower values commonly reduce variation. top_p controls nucleus sampling. An output-token limit caps output length; it does not add knowledge. Check the model's supported parameters before filling API blanks. Lower randomness does not guarantee correctness, schema validity or identical outputs.

Structured-output trap: Chat Completions commonly uses response_format; Responses uses text.format. A json_object setting targets valid JSON. A supported strict json_schema constrains structure. Parse the result, validate types/business rules and handle refusals or incomplete output. Valid JSON can still contain false facts. Structured outputs

RAG has two separate pipelines

Before questions arrive: collect content → extract/OCR → chunk with metadata → embed → index → keep updated.

When a question arrives: identify user/context → retrieve authorized, current passages → optionally rerank → supply evidence to the model → generate/cite → validate or abstain.

Preserve title, URL, page/segment, parent document, version/effective date and access metadata where needed. Vectors help find content; send the actual retrieved text/evidence to generation. A vector or similarity score alone is not a readable supporting passage.

Typical failures: no new documents → investigate ingestion; relevant document missing from top results → evaluate retrieval; good passages but unsupported answer → inspect generation/groundedness; cited old policy → repair freshness and validity filters. Citations show provenance, not automatic truth or currency. RAG architecture

Foundry IQ and agentic retrieval

Foundry IQ organizes reusable knowledge integration instead of embedding a separate private knowledge copy into every agent. Agentic retrieval can plan subqueries, retrieve evidence and combine it for complex questions. The knowledge source/index still needs ingestion, permissions and freshness. It does not replace a customer's conversation or per-user memory. Agentic retrieval

SFT versus DPO versus RFT

MethodData/training signalGood fitExam anchor
SFT: Supervised Fine-TuningPrompt + demonstrated ideal outputConsistent format, domain response behaviorImitate examples
DPO: Direct Preference OptimizationPrompt + preferred/rejected response pairImprove preference alignment, tone or response choicesPrefer one output over another
RFT: Reinforcement Fine-TuningPrompts + sampled outputs scored by a graderVerifiable domain reasoningOptimize numeric rewards

All three update weights. RFT needs a reliable scorer; it does not require a fully written ideal answer for every prompt. DPO's preference pairs differ from an RFT grader scoring newly generated candidates. Fine-tuning methods

RFT: the complete loop

  1. Select a reasoning model that already has some competence at the task.
  2. Prepare representative training prompts, grader reference data and separate validation examples.
  3. Define and test a grader: deterministic code, model rubric or combined checks.
  4. During training, sample candidate solutions and score them.
  5. Update model weights toward behavior earning better rewards; repeat.
  6. Compare held-out performance, investigate reward hacking and select a validated checkpoint.
  7. Deploy the trained model; monitor real task quality.

Example: generate code → run tests → 4/10 tests pass gives an illustrative reward of 0.4; 10/10 gives 1.0. Training encourages more successful solutions across examples. Rewarding only superficial formatting could teach the model to format beautifully while solving incorrectly.

Use RFT when success is reliably checkable: calculations, code tests or application of complex rules. It is a training process, not automatic learning from each production conversation. Microsoft RFT, RFT use cases and grader limitations

Study by decision

  • Prompting vs RAG vs fine-tuning — 4 questions. Prompting specifies behavior; RAG supplies current/private evidence; fine-tuning learns repeatable behavior from training signals.
  • Grounding, citations & missing evidence — 4 questions. Retrieve applicable current evidence, cite the supporting source and refuse or escalate unsupported conclusions.
  • Task instructions & domain analysis — 7 questions. Specify task, scope, output structure, evidence rules and unknown-value behavior. Evaluate against representative domain examples.
  • Temperature, reasoning & token settings — 9 questions. Use supported generation controls for the specific model. Lower temperature reduces ordinary sampling variability; reasoning effort and output token limits control different behavior.
  • JSON syntax, schema & factual validation — 17 questions. Request supported schema-constrained output; validate required fields/types and check values against evidence/business rules.
  • SFT vs DPO vs RFT — 3 questions. SFT learns target examples; DPO uses preference pairs; RFT uses grader rewards for sampled outputs during training. Evaluate on held-out data.
