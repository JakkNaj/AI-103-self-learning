Evaluation versus observability

Evaluation: was the answer/process good? Tracing: what happened in this run? Metrics: how is the system behaving across runs? Use them together: a quality score detects regression; a correlated trace helps explain it.

Agent evaluation must inspect the process as well as the final sentence. A plausible final answer can hide a failed action. Exact evaluator names/support can differ by SDK/service version. Built-in evaluators

Groundedness is narrower than correctness

Groundedness asks whether the answer's claims are supported by the supplied evidence. A perfectly supported answer based on an expired policy can still be wrong today. Relevance asks whether it answers the question; fluency/coherence asks about presentation. Do not substitute a fluent answer for an evidenced, complete answer.

Groundedness needs answer and supporting context. Retrieval evaluation investigates the selected evidence, optionally against relevance labels/ground truth. Evaluate missing information and correct abstention, not just successful cases. RAG evaluators

Offline evaluation and release order

  1. Define task requirements, expected behavior and measurable acceptance criteria.
  2. Build representative cases: ordinary inputs, edge cases, missing evidence, tool failures and attacks.
  3. Separate tuning examples from held-out evaluation data.
  4. Run candidate prompt/model/tool/retrieval configuration.
  5. Score the relevant dimensions and inspect failures.
  6. Fix causes; repeat affected checks against a baseline.
  7. Gate release on thresholds, approved configuration and rollback readiness.
  8. Monitor sampled production quality and operational behavior after rollout.

An LLM judge/self-critic can be useful, but it needs a tested rubric and cannot grant business authorization. An evaluation result does not itself retrain model weights. RFT uses a grader inside a separate training process.

What a useful trace contains

Correlate request/conversation → retrieval spans → model spans → tool calls/results → approval → final output. Record identifiers, timing, errors, model/deployment/version and source provenance as appropriate. Record sensitive content only under an explicit, minimized retention/access policy.

Example: 15-second answer → trace shows retrieval 0.2s, first model 1.1s, external tool 12s, final model 1.7s. The external tool is the latency bottleneck; changing the answer prompt may not address it.

For unsupported output with correct tool data, inspect the model step after that tool. For skipped tools, inspect selection/configuration. For malformed arguments, inspect the call contract and validation path. Agent tracing

Instrumentation and production questions

Connecting Application Insights is a destination setup, not proof that every component emits spans. Instrument custom client validation/dispatch and external components; propagate correlation. Distinguish services/libraries with appropriate resource attributes or instrumentation scope.

Disabling content recording reduces captured payloads; it does not prove secrets cannot appear in custom span attributes. Never put credentials into prompts/tool descriptions/ordinary logs. PII controls should precede broad transcript logging.

Continuous evaluation can score a configured sample of real production interactions. It differs from a prerelease test set. Its runtime identity needs the documented project permissions; an engineer's portal access does not authorize a background evaluation identity.

Operational dashboards need latency/errors/429, input-output token use, retrieval freshness/indexer failures, grounding/relevance and safety events. Average latency or token count alone cannot detect all quality/safety regressions.

Study by decision

  • Groundedness, relevance, completeness & retrieval — 30 scored questions. Groundedness checks support; relevance checks answering the question; completeness/response completeness checks expected information; retrieval metrics inspect evidence selection.
  • Tool selection, arguments & task success — 13 scored questions. Evaluate tool selection, argument correctness, execution/result handling and end-to-end task completion separately.
  • Traces, spans & correlation — 23 scored questions. Instrument server/client spans with correlation, timings, outcomes and safe metadata; inspect the actual failing path.
  • Token usage & cost attribution — 8 scored questions. Separate input tokens, output tokens, model rates and additional tool-driven model rounds; compare versions and workloads.
  • Continuous production evaluation & dashboards — 10 scored questions. Evaluate configurable production samples and combine quality, safety, latency, failures and usage signals. Correlate regressions with traces.
  • Held-out datasets & release quality — 5 scored questions. Use representative held-out data and explicit quality/safety/task criteria to compare releases.
  • Citations, asset versions & reproducible audit — 14 scored questions. Retain applicable source version/location, model/deployment/prompt/tool configuration and approved output identifier.
